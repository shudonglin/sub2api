Pick an approach

A

New Repo (Recommended)

3 repos, 3 concerns, 3 hosts

Create a new repo (e.g. sub2api-web) with a static site framework (Astro, Next.js static, or plain HTML+Tailwind). Deploy to Cloudflare Pages. Each repo does one thing well.

Pros

  • Clean separation — landing page is pure marketing/docs
  • Deploys instantly on Cloudflare Pages (free, global CDN)
  • No impact on backend or payment repos
  • Can use any static framework

Cons

  • One more repo to manage
  • Need to keep API docs in sync manually
B

Add to sub2apipay

Landing page as routes in the existing Next.js app

Add /, /docs, /pricing routes to sub2apipay since it's already Next.js. Export static pages for Cloudflare, keep payment routes on VM.

Pros

  • No new repo
  • Shared codebase (styles, components)

Cons

  • Mixes marketing with payment logic
  • Complicated deploy: static export for some routes, server for others
  • sub2apipay needs PostgreSQL — can't fully run on Cloudflare
C

Add to sub2api (Vue)

Extend the existing Vue frontend with public pages

Add landing/docs pages to the existing Vue frontend alongside the admin dashboard.

Pros

  • No new repo
  • Co-located with the API gateway

Cons

  • Tied to the VM — can't use Cloudflare Pages
  • Vue frontend is designed as an admin SPA, not a public site
  • SEO challenges with SPA
  • Couples marketing to backend deploys
